## 独立保存与恢复

独立保存清单记录相对路径、字节数、SHA-256和权限。**本轮仅生成清单，没有创建额外备份，也没有指定硬盘、NAS或网盘。** 当前工作目录仍是这些文件的实际保存位置；Git仓库本身不会包含它们。

后续归档应按清单复制文件并保留目录层级、可执行权限及许可文件，同时保存该版本的清单。完成归档并核验前，保留现有文件。将来如改用Git LFS，另做明确迁移，不把本方案清单当作LFS指针。

在新电脑上先取出对应Git版本，再将同版本资源恢复到工程根目录。恢复后执行：

```sh
python3 tools/repository/audit.py verify-archive \
  --manifest qa/git-first-commit-20261030/archive-manifest.json \
  --root .
```

核验通过仅表示资源与清单一致；引擎运行、正式构建和发布验收仍单独进行。新检出副本缺少外部资源时无法完整构建，不应误判为Git内容损坏。

## 后续维护

修改资源或规则后生成新批次，不覆盖旧清单：

```sh
python3 tools/repository/audit.py inventory --out qa/git-layout-YYYYMMDD-新批次
```

工具在系统临时目录创建Git元数据，用真实Git规则检查文件范围；不修改工程Git状态，不暂存。它还检查冻结快照的字节指纹，以及现存候选输入清单的路径覆盖。新增未归类文件、遗漏构建输入或指纹不符时会失败。

历史`build/`和`dist/`目前保留原位；各历史版本不能仅凭当前源码保证重建。后续确定正式发布候选时，应另存该候选的冻结输入、构建清单与分发包，再决定旧输出的保留期限。本轮没有清理它们。
