## 2. 资源现状与来源白名单

当前工程没有 `assets/current/` 正式采用库。根 `images/`、`system/`、`suika-beat/` 与SDK内共530张位图已读取格式、尺寸和指纹，全部隔离为示例材料（仅初次盘点集合，不含后续SUI-U新资源），见[本地示例盘点](../../qa/SUI-A01-20261028/local-sample-inventory.json)。SUI-U另交付103项GUI，每项含PNG与等像素WebP，属于界面任务成果，不能归入SDK示例或角色/场景/CG采用。本任务只读其接口与验收记录，不接管资源。SUI-T的10张历史图是负载样本，不算正式采用，也不算A/B方案完成。

历史来源按人物页链接、`assets/README.md`、`current-art.json` 及有记录的路径迁移追溯。精确白名单记录203个实读文件、172张成功解码的位图；其中旧采用库162张，合计215,882,624字节，分为角色89、背景55、CG14、封面2、海报2。其旧清单指纹与尺寸162项均吻合；**旧“采用”状态不继承至本工程**。本轮只验证文件与记录，不作这些图片的视觉终审。

白名单分三层，按JSON字段执行：

1. `files[].permission=read_only_audit`：仅允许审计列出的精确路径。每项有读取原因、SHA-256及大小；不能据此递归复制所在目录。
2. `referenceCopyEligible=true`：后续对应制作包确有依赖时，才可单文件复制到 `assets/sources/<批次>/<任务ID>/` 作参考。必须保留来源、指纹、使用范围；不代表图片已通过新稿复核。
3. 所有 `copyToCurrentAllowed=false`、`adoptedInSuika3=false`：A01不授权运行采用。A11提供检查与待采用记录，SUI-I唯一导入批准图。

未实际读取的历史提示路径只记在 `sourcesRecordedNotRead`，不属于已核验白名单；路径改名必须能追溯到迁移记录。旧部署、旧QA整库、旧Git、缓存、旧JS播放器与 `story.js` 不导入。历史CG14张与新版52个保留编号尚未逐镜映射，不能用“有14张旧图”抵扣制作缺口。

- 角色：`char-<人物键>-<形态>-<衣装或base>-<差分>-v001.webp`。
- 背景：`bg-<场景键>-<时间或状态>-v001.webp`。

以上是新文件约定，不批量改名旧图库。逻辑`assetId`跨文件版本保持稳定，源文件、衍生文件和SHA-256分别记录；模板顶层元数据仅描述衍生图，原图另填`sourceMetadata`，每种兼容格式各填一份记录；替换时写`supersedes`和影响范围，不能仅靠文件名声称新版本获批。全作运行资源键及美术状态恢复契约尚待E/I冻结。E现有构建的`resourceBindings`仍为空；不因入口已接入而视为资源集成完成。

### 负载与格式验收

T的10张样本实际编码量12,353,550字节（11.78 MiB）；按`宽×高×4`估算RGBA合计62,919,024字节（60.00 MiB）。这是全数同时解码的理论像素量，**不是峰值内存实测、不是完整游戏容量，也不是性能通过标准**。

建议首轮运行衍生以单张2 MiB、最长边2048像素作为超限复核提示，不作为硬性拒收规则；旧原件无须为满足提示而改写。超限先比较画质、显示尺寸、解码开销和实际设备结果，不能为压缩体积破坏透明边或关键细节。全作包含52个保留CG需求，不能从10张样本推出整包可承载结论。

初次盘点发现T诊断JPG误入包；续作核对时已从127项白名单剔除，当前资源包32,737,328字节。原发现与最新修复分开记录于技术对齐，不把已修问题继续列为阻塞。T网页验收和U独立UI验收均引用各自报告，本任务没有重跑。当前Wasm线性内存512 MiB，正式全作峰值与真实手机仍待实测。

T/E需基于正式资源给出包体、首次加载、是否整包下载、同时驻留图片数、切图峰值及真机内存的测量结果，再确定全作预算与装载策略。A11逐图交接`bytes`与`width×height×4`，不能自行假设引擎支持分包或延迟加载。

无损检查真实格式、尺寸、方向、可见解码像素及alpha；透明像素隐藏RGB如有变化单列，不把它混同可见画质变化。有损检查肤色、文字、渐变、毛发及边缘。书本/手机内容若须可读，先由正文与U提供确切文字，不让生成图补造日期、姓名或剧情事实。
