# 电影侧栏 UI

2026-10-30。用户在三方案中选择“方案三”。本作剧情选择与系统页面采用深蓝黑底、暖米色强调、左对齐文字和侧栏分类。当前候选 `sui-i02-20261030-cinema-v7`；[本机预览](http://127.0.0.1:49257/)。当前静态B封面与底部四入口继续使用封面清单中的采用结果。

## 已实现的界面

- 剧情选择：右侧480×80按钮，间隔8，最多六项。134个选项逐项按实际Noto Sans CJK字体度量；普通选项最多两行，路线入口显示人物名与正文中的行动。原生选项文字和值保留，呈现由可重建的文字图完成。
- 人物避让：选择期间将完整场景等比呈现在左侧742×418区域，人物、道具和背景一起缩放。仅在渲染调用期间改变图层位置/缩放，渲染后立即恢复；不改正文演出绑定、原始图片、存档舞台或下一段位置。
- 系统分类：阅读菜单、存读档、阅读回顾、阅读设置、图鉴。固定左侧导航；保存/读取在内容页顶部切换，返回位置固定在左下。设置保留五种原生滑杆、阅读预览、重置和全屏；阅读菜单保留自动、快进已读、回退和返回标题。
- 回顾和图鉴：沿用原生历史、CG解锁和翻页逻辑；图鉴仍每页六项、十页，未解锁项不显示标题或缩略图。可从正文菜单直接查看图鉴并返回原段；打开全图时暂时占满画面。
- 输入：鼠标/触摸仍由原生选择框接收。上下键循环聚焦，回车写入现有原生选择变量并进入同一个提交检查；鼠标移动后恢复指针焦点。没有新增统一二次确认流程。
- 保存提示移到不遮挡导航和正文的底部信息区。

## 存档与版本

沿用1自动＋3手动档、原生存档格式、版本检查、剧情状态校验和选择前检查点。新候选使用新的构建身份，旧档原位保留且不按行号迁移，新版需要重新开始。

本次检查发现：当前SDK在某一槽为空时，刷新后可能不登记后续槽位的元数据；实际保存文件仍存在。对照[上游存档初始化实现](https://github.com/awemorris/suika3/blob/main/src/save.c)，读取基本信息的循环遇缺槽即退出，与实测现象一致。本实现为成功保存的槽额外保留全局时间/章节/末句信息，在原生缓存缺失时用于列表识别，并仍由原生读取及已有校验决定能否恢复；不补写任何空槽，不修改SDK。此情况下缩略图用“已保存 · 点击恢复”文字占位，原生缓存已有的槽继续显示原缩略图。

## 可重建入口

```sh
node tools/ui-cinema/build.cjs
node tools/integration/runtime/build.cjs --version <新的候选名称> --snapshot qa/dialogue-expressions-20261030/snapshot.json
node tools/runtime/serve.cjs --web dist/<新的候选名称>/web --port <新的本机端口>
```

- `tools/ui-cinema/`：从当前编译结果提取选项，生成GUI位图和字体度量；正文变化后必须先重建。
- `assets/sources/20261030-cinema-ui/`：选项布局登记、PNG原件与等像素无损WebP。
- `assets/current/ui-cinema/`：批准的运行衍生，当前SDK使用PNG；无损WebP保留，不直接接入有通道兼容问题的原生GUI。
- `system/sui-cinema/manifest.json`：采用指令、画布、资源指纹、GUI映射和正文版本。此UI清单独立于角色/场景/CG的I01采用清单。
- `system/sui-cinema/runtime.ray`与`tools/runtime/cinema-theme.cjs`：原生界面补充与构建适配。旧`system/sui-u/`及其历史验收保留；主题只覆盖构建输出，不回写原资源。
- 构建会校验资源指纹及UI/正文版本，冻结工具、资源、GUI和原生辅助代码后生成网页与电脑平台文件。
