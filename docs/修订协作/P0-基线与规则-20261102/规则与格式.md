## 编辑粒度

每次处理一个完整场景组或一章，带齐A/B、共同段和前后条件；互斥段不能拼成连续经历。先记时间地点、在场与远程人物、各人已知信息、物品归属、前置选择、当场变化和后续回收。

对白承担行动、信息或关系变化；保留必要环境、动作与心声，不把心理活动都说出口。每条对白一位发言者，动作另段。保留人物口吻，不用对白占比或字数配额凑篇幅。十四结局各检查“决定有来由—对方回应—生活落点”，已有有效场景计入约2—3段短场景，不机械追加尾声。

本约定借用screenwriter的场景拆分和chinese-novelist的对白／连贯性检查；不把短片XML、小说字数配额或统一悬念结尾写入本作。

## 稳定标识

[基线段落登记](../../../qa/dialogue-p0-20261102/paragraph-registry.json)已为3,018个原文段落分配 `T-<文件码>-<六位序号>`，逐条保存源文件、SHA-256、旧段落／分页ID、旧绑定ID与条件。序号只在首次分配时按原文顺序产生；此后不重排、不回收、不由文本哈希重新生成。

| 文件码 | 来源 |
| --- | --- |
| C01 / C02 / C03 | 共通第一章／第二章／选线章 |
| XM / ZZ / MY / PI / HQ / FR | 六条路线；PI的HIGH/LOW共享编号空间 |
| D36 / EPH / EPL | 公共第36天／HIGH后日谈／LOW后日谈 |

- 最终定位使用 `file + id`；ID在全稿全局唯一。行号、摘录和旧哈希只用来复核冻结来源，不承担改稿后的身份。
- 改字但仍为同一人物、媒介、叙事动作与条件，可保留ID并更新版本指纹。改变含义或分支作用时重新分配。
- 一段拆成多段：旧ID退役，所有新段各领新ID，记录一对多来源。合并多段：旧ID全部退役，另领一个新ID。删段保留退役记录及线索去向；新增段说明依据，不能伪造来源。
- 新ID从登记的 `nextSerial` 续领；不同路线可各用自己的文件码，同一文件由一人分配。共享文件和登记表由总编合并。移动段落不重编号，跨文件移动需明确登记所有权与条件变化。
- 可选 `group` 使用 `G-<文件码>-<六位序号>` 标识同一演出段，不能跨换场、选项、IF分支或CALL/RETURN；未审定填null。group只归组，不决定路径。
- 旧绑定只供追溯。拆分、合并、移动或文字变化一律标为待审，不按行号、文本相似度或ID相同直接继承人物、CG和退出恢复状态。

## 源稿语法

现有NODE、IF/ENDIF、选择、选项、结局、CALL/RETURN、EVENT、FREEZE与EPILOGUE的含义和顺序不变。不得给每句对白插入NODE：现有解析器用最近NODE判断CALL/EVENT来源，会破坏控制流。

新格式采用**单行TEXT注释＋一行正文**，段落之间空一行。注释使用严格JSON；未知字段、重复ID、非法枚举和缺字段应报错。它只描述紧随的一个正文段，不跨标题、条件或选择边界，不允许一个标记覆盖两段。

```text
<!-- TEXT {"id":"T-C01-000016","kind":"dialogue","speaker":"shijiang","name":"师匠","channel":"face","group":null} -->
晚上十点到早上六点，月薪两千。休班提前排，工资每月固定一天结。夜里管一顿饭。愿意做，我们把话讲清楚。
```

上例为源稿原句的格式说明，ID须以实际[小样夹具](../../../qa/dialogue-p0-20261102/format-fixtures.json)为准，不能把示例编号直接占用到别的句子。正式字段校验表见[格式约定数据](format-contract.json)。

| 字段 | 约定 |
| --- | --- |
| id | 已分配且唯一的稳定段落ID；不使用旧TEXT哈希ID |
| kind | `dialogue`实际发言、`message`文字消息、`thought`明确心声、`narration`旁白、`action`纯动作 |
| speaker | 角色登记键；旁白／动作必须null；未知人物也先登记场景限定键，不借用另一人的身份 |
| name | 该段此刻允许显示的名字／身份；旁白／动作必须空字符串；不从立绘推断 |
| channel | `face`当面、`phone`电话、`video`视频、`voice`语音／游戏麦、`offscreen`现场画外、`text`文字消息、`inner`心声、`none`旁白／动作 |
| group | 已审定演出段键或null；与控制NODE分开 |

组合限制：dialogue只可用face/phone/video/voice/offscreen；message只能text；thought只能inner，第一人称心声限文文，不能代写别人没说出口的想法；narration/action只能none。人物姓名必须来自[角色称呼表](角色称呼表.md)中该情境允许的称呼。

对白正文不再加包住整句的外层引号，也不重复“文文：”“她说”；句内引用保留中文引号，原本必要的动作另起段。文字消息明确发送者，不从“他回了”猜姓名；一条群聊消息对应一个发送者。未知来电和电台主持分别登记，不冒充在场人物。

## 显示与恢复要求（P1验收项）

姓名由当前段的显式数据决定。phone/video/voice/text/inner分别加“（电话）／（视频）／（语音）／（消息）／（心声）”；face不加后缀，offscreen不暴露门后身份。姓名与立绘可独立存在，远程发言不自动出现现场立绘。

旁白、动作、选择提示、结束页必须清空姓名；换人立即切换，同段分页保持姓名。每页定位为稳定段落ID加页内位置，分页索引不是段落身份。回顾、自动、快进、回退和读档从相同字段恢复，CG全图返回也不能串到另一分支。

P1可以在独立小样中允许未迁移旧段按旧规则读取，但不能自动猜发言人；P2定稿后新版覆盖范围内缺TEXT必须拒绝。新增元数据必须进入构建指纹与存档版本判断，旧档保持原样，新候选从头开始；P0映射不是跨版本存档迁移授权。

## 回稿与采用

中文模型只提交待采用稿，附输入指纹、完整段落、改动原因、分支／新增信息／疑问与来源映射，不直接修改清单或条件。回稿至少包含：

```json
{
  "baselineFingerprint": "填写本批baseline.json中的fingerprint",
  "sourceBuildId": "填写本批contentBuildId",
  "changes": [{
    "operation": "split",
    "oldIds": ["原段落ID"],
    "newIds": ["已领取的新ID1", "已领取的新ID2"],
    "reason": "拆开原有动作与单人发言",
    "conditionChanged": false,
    "bindingReview": "pending"
  }],
  "unresolved": []
}
```

总编核对当前源指纹、完整性、受保护标记、人物知情与时间／物品连续性后回写 `scenario/`；P3统一合审冻结，P4才采用演出与新图。涉及新事实的问题由用户决定，不能用空 `unresolved` 掩盖未解决项。
