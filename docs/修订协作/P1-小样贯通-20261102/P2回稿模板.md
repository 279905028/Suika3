# P2 分批回稿模板

每批覆盖一个完整场景组或一章，带齐 A/B、共同段与前后条件。先读当前 `scenario/`、人物资料、规则契约、称呼表及本批来源指纹；不把其他分支当作已发生经历。

## 回稿内容

1. 输入：来源文件、SHA-256、覆盖的稳定段落 ID、前后场景、选择与条件。
2. 问题与处理：原句、问题、最小修订理由；需要新增设定时先列疑问，不补造婚史、日期、疾病、家庭经历或人物知情。
3. 完整候选正文：不省略共同段、互斥段或结尾；保持选择 ID、文案、事件及分派语义。
4. 来源映射：保留／拆分／合并／删除／新增、旧 ID、新 ID、理由、条件是否变化、待审演出。
5. 新增信息、未决问题和可选画面建议。候选不直接写正式绑定。

## 可编译格式

每章必须有“完整内容”边界。以下沿用网吧原句，仅演示格式；**编号已有主人，不可复制到另一句或另一文件**。

```markdown
## 第一章｜场景标题

### 完整内容

<!-- TEXT {"id":"T-C01-000016","kind":"dialogue","speaker":"shijiang","name":"师匠","channel":"face","group":null} -->
晚上十点到早上六点，月薪两千。休班提前排，工资每月固定一天结。夜里管一顿饭。愿意做，我们把话讲清楚。
```

- TEXT 用严格 JSON，且只对应紧接的一行正文；段间空行。不能跨标题、导航、条件或选择，也不能一条标记管两段。
- 单人发言与动作拆开；对白不重复姓名前缀或整句外层引号。句内引用可保留。
- `dialogue` 用 face/phone/video/voice/offscreen；`message` 用 text；`thought` 用 inner 且限文文；`narration/action` 用 none、speaker=null、name=""。
- 媒介后缀由编译器添加，源稿 `name` 不重复写“（电话）”等。未揭身份使用已登记的当前称呼，不提前揭名；新增人物先据原稿登记。
- `group` 未审定填 null，不能跨换场、选项、条件或 CALL/RETURN。它不替代 NODE，不参与剧情判定。

## 编号与合并

P0 登记保留；已分配 ID 不重排、不回收。一拆多或多合一时旧 ID 退役，新段各领新 ID，逐项保留来源。三个 P1 候选已占用的候选序号：C01 至 275、PI 至 645、MY 至 555；下一候选序号分别为 **276／646／556**。这些尚未写入正式登记，采用前由总编核对并统一领取，避免与其他窗口撞号。

同一文件顺序合并，共享规则与编号登记由唯一负责人维护。采用时核对输入指纹，保护现有未提交修改；不能把 P0 快照覆盖回当前正文。

## 每批采用前检查

- 明确说话人、当面／远程关系、信息来源和场景连续性；动作不挂姓名。
- 保持六线十四结局、孟遥 AA／AB／BA／BB、飘 HIGH／LOW、第36天与单身后日谈门禁；叶岚不新增攻略线。
- 对照控制标记、选择文本、段落来源及新信息；全部演出变化标“待 P4 审阅”，不凭旧行号或相同 ID 直接继承。
- 在隔离输入中做格式和规则校验；全部覆盖范围迁移完成后使用 `required`，不能用 `mixed` 掩盖漏标。
- 结尾包含决定的来由、对方回应和生活落点，已有有效场景计入约 2—3 段短场景，不机械追加同样的尾声。
