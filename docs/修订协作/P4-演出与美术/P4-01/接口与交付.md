# P4候选格式与运行接口迁移

本接口只管理演出候选和审阅交付。正文来自P3冻结候选，正式采用由P4-07执行。机器字段见[schemas.json](schemas.json)，检查器见[validate.cjs](../../../../tools/story-revision/p4-bindings/validate.cjs)。

## 输入定位与版本

所有包的四份JSON顶层均包含`schemaVersion=p4-package-v1`、`packageId`、`inputFingerprint`和`contentBuildId`。后两项分别对应P4冻结输入与P3正文版本，必须完全一致。输入清单和接口清单分别有自校验指纹；任何依赖变化均拒绝继续沿用。

`paragraph-map.json`记录稳定段落到分页的一对多对应及P0/P3来源。`node-map.json`记录显示节点；正文页是`T-文件码-序号_页数`，选择继续使用已有选择ID。选择归所属源文件所在包，不能复制到相邻路线包。TEXT姓名和媒介由正文决定，不从画面推断。

旧绑定版本为`sui-i01-epilogues-20261102-v6`，登记构建ID为`bafc873cdc8b681b64ec83115e3a0bc8108e4fca470d53fea89492742ff4915c`。当前编译器已包含P1的TEXT支持，用它重编旧正文得到`c3a2057066a955fe3365cbbce949548f9c78536a7d8f2a8b6edaa12c92e7c393`。本批核对了旧正文SHA-256、3,085节点锚点及旧绑定来源一致，**没有把两个构建ID当作相同版本**；旧画面仅作追溯，不能重新声称旧包运行已验。

## 四份包交付

| 文件 | 内容与门禁 |
| --- | --- |
| `bindings.candidate.json` | `bindings`数组逐节点一条`{nodeId,binding}`。待审为`binding:null`；填写后payload必须满足当前SUI-I-1绑定结构。所有4,814显示节点按包完整覆盖，无重复/越界。 |
| `review.json` | `reviews`数组按稳定段落及选择各一条：`unitId,nodeIds,status,decision,basis,needIds,unresolved`。`status`仅pending/reviewed/blocked；已审需实际依据、决策及空未决项。 |
| `needs.json` | `needs`数组统一收缺图、镜头及返修需求；没有新增需求可为空，但复用/留白依据仍须逐段写入review。需求必须双向关联本包节点与review。 |
| `boundary-states.json` | 每个分配边界一条：`boundaryId,status,exitPolicy,restorePolicy,basis,unresolved`。边界对象的目标、规则和跨包对象见冻结清单，不自行改写。 |

`review.decision`为`reuse/rebind/neutral/new-art`。reuse表示复用既有资产而重新确认本段适用性；rebind表示调整组合、位置、进退场；neutral是有依据的空画面；new-art必须关联制作需求。任何选择都不允许跳过逐段审阅。

草稿可带待审与开放需求；交接模式拒绝未审、空绑定、开放需求和未通过本批检查的资源。检查器验证结构、指纹、覆盖和声明一致性，不能判断人工依据是否充分，也不能代替目视、用户批准或引擎实测。P4-07仍须核对交付证据。

## 完整画面与生命周期

新绑定ID固定为`p4-<nodeId>`。`anchor`的nodeId、file、sha256须精确取自映射；不使用行号匹配。`condition`须精确复制冻结节点条件，`routeIds`须精确相同；不能把条件化节点改成ALL、增加未来选择条件或另加路线门禁。

`enter`与`exit.restore`均有`background,characters,props,cg`四项；null/空数组明确清除，缺字段拒绝。坐标、层、缩放、形态和衣装沿用SUI-I-1。资源存在不等于可用：交接时还要有P4复验及批准依据。

- 退出使用`exit.at=next-node`，`exit.restore`等于本页enter去掉CG后的完整底层；随后由目标节点完整重算。不能把源场景带入另一分支。控制节点期间的实际绘制行为由P4-06/P5验证。
- 回退、改选和读档均按目标节点重建；边界声明固定`clear-before-target`与`recompute-destination`，不会保存一个可被误当目标画面的源场景快照。
- 同段分页保留姓名、媒介及完整画面；本次唯一跨页段两页须一致。
- 选择可保留经本包明确审定的背景和现场人物；必须清姓名，禁止CG与全图模式。
- CG只能在正文页显式绑定，`cgId`须与登记图片一致，`fullView=true`；无CG时两字段分别为null/false。全图不推进正文，实际可见帧才解锁图鉴；P4-06负责保持这些运行语义。
- 当面、电话、视频、语音、消息与画外应逐段确认。远程说话人不自动出现场立绘；元数据不等于已经审定画面。

文件入口、分支/汇合、选择、分页、五个公共事件调用及返回、十四结局和后日谈分派均列入边界清单。COMMON→路线、路线→公共事件→路线、结局→后日谈/结束须两侧各自提供依据，由P4-07对照；目的地属于另一包时只提出约束，不代写对方状态。

## 缺图与镜头需求

每项需求字段固定为：

- `needId`：本包前缀，例如`P4-02-PI-N001`；`resourceKey`标识同一人物/场景/镜头需求。
- `kind`：character/expression/background/prop/cg；`action`：reuse/offscreen/new/repair；`ownerTask`：CG归P4-04，其余归P4-03。
- `nodeIds`：本包精确新节点；其条件、稳定段落和媒介从映射读取，不另造条件字符串。`reason`及`constraints`写明冻结正文依据、在场/远程、形态、衣装、道具、进退场及待确认问题。
- `existingAssetIds`列可参考的既有图；`proposedAssetId`和`cgId`未分配时为null。编号由P4-04统一分配，禁止复用退役CG。相同resourceKey的跨包需求由03/04汇总为一个制作任务，不能多窗口各自生产。
- `status`为open/resolved/cancelled。open的resolution必须null；关闭需`resolution={assetId,reason,evidence}`，evidence为非空`{path,sha256}`数组。resolved且不是offscreen时须指向有效且类型匹配的资源；取消或留画外时assetId必须null。

制作包先读冻结原文和人物/场景依据。不清楚的剧情设定交用户决定。需求关闭不直接修改正式资源清单。

## P4-05资源目录与CG登记

[资源基线](resources.baseline.json)提供统一形状`p4-resources-v1`。P4-05交同格式的候选目录，保持P4输入指纹：

- `assets[]`：assetId/type、source/runtime的路径与SHA-256、reviewStatus、approvalEvidence、checkEvidence。reviewStatus为pending/passed/rework；passed必须引用批准依据和本批`qa/dialogue-p4-...`的检查证据。历史A11记录只能作来源，不能充当本轮复验。
- 新增或返修图先放各自`assets/sources/`制作/检查目录，运行衍生也可暂存该处；正式`assets/current/`由07采用。检查器核对实际文件字节；格式、尺寸、alpha、无损/编码及目视结论写在P4-05证据内。
- `cg[]`：cgId/assetId/registrationEvidence。保留既有编号对应的资源ID，修图在同资源ID下交新文件；新增编号须引用P4-04目录或其QA的登记证据。无固定60项上限，但现行运行器仍有60项约束，须P4-06修改与验证后才能接入增图。

既有资源引用可在draft阶段填写；未检查新图保留pending，无法通过完成交接。不得用批准备用或占位图冒充已完成需求。

## 与现有接口的明确迁移

计划中的[interface-i01-v1.json](../../../整合/interface-i01-v1.json)是早期`diagnostic-cues-only`接口：逐cue、typed entry gates、选择清美术。当前v6实际已使用[interface-v1.json](../../../整合/interface-v1.json)的`SUI-I-1`完整节点状态；本次候选payload与后者兼容。

| P4字段/行为 | P4-06/07消费方式 |
| --- | --- |
| `bindings[].binding` | 校验后展开为SUI-I-1的bindings数组；审阅字段不发送给运行器 |
| P3构建ID/新source hashes | 正式采用时同一批次重新编译，刷新资源、绑定、UI与快照版本；不沿用旧v6构建ID |
| node-map的entryGate | 记录来自正文控制流的route/sharedEvent/epilogue上下文，不作为运行payload新增字段；条件仅在游标命中后求值 |
| 显式完整状态、跨页逐页绑定 | 沿用当前v6状态组合；选择可保留已审场景，区别于早期诊断接口的清空规则 |
| 资源复验和新增CG | 06实现候选资源接入、A11/P4证据衔接、图鉴容量及解锁；07统一采用并锁定全部文件 |

01没有改运行器，也没有解除当前60CG和旧资源证据格式限制。格式通过仅说明后续工作输入一致；P4-06实现与P5运行验收仍独立记录。
