# SUI-T 原生样板实现说明

2026-10-28。范围仅为本目录技术样板；正式 `scenario/`、根入口和 SDK 均未改写。最终运行结论以本批次交接及浏览器实测记录为准。

## 原生职责

- `native/main.ray` 使用 Suika 原生 `start/update/render`，运行画布 720×1280。JavaScript 不保存剧情状态。
- `native/start.novel` 引用第一章第15—33行，原字保留、显式分两页；逐页来源和 SHA-256 在 `native/source-map.json`。其余文字均为样板说明，不构成新剧情。
- `choose` 使用稳定路线 ID。前四项为罗小满、周栀、孟遥、飘；黄球球仅在三个已登记前置均为1时出现；朋友与职业始终可见。提交后再次检查前置与 ID 白名单。
- 前置均为带 `spike_` 前缀的测试状态，不提供飘的关系阈值，也不宣称六条正式路线已编译。
- 10张白名单WebP由原生标签逐张解码并展示；包内保原尺寸，画面通过原生缩放适配纵屏。字体和ogg来自当前工程SDK示例，仅作技术依赖。

## 存档和控制

| 操作 | 键位 | 含义 |
| --- | --- | --- |
| 保存 | S / D / F | 原生手动槽1 / 2 / 3 |
| 读取 | 1 / 2 / 3 | 原生手动槽1 / 2 / 3 |
| 读取自动档 | A | 原生槽0 |
| 继续 | Enter / 点击 | 原生文字推进；Space 为引擎隐藏正文行为 |
| 返回选择 | C | 重新计算条件并呈现选择 |
| 全部前置切换 | U | 000与111之间切换 |
| 单前置切换 | 4 / 5 / 6 | C01-02=A / C02-01=A / day14已读 |
| 下一资源 | N | 10张真实资源循环 |
| 重新开始 | R | 重置样板状态；保留三个手动档 |

自动档在中文、选择、选中路线和图库检查点进入稳定的text/choose等待后写入。刷新启动若已有槽0，先原生读档再更新脚本，防止boot覆盖已有自动档。手动及自动档均调用 `executeSaveLocal/executeLoadLocal`。键盘执行按下边沿检测。成功读档后不再移动脚本位置。

日志前缀 `SUI_T|`，包含操作、槽位/条件、stage、route、hq、tag。Wasm版Ray print会触发alert，网页壳需将该前缀转成控制台事件；其它错误不得吞掉。

## 验证边界

原生API来自当前 `SDK/documents/ray-vn-api.html`、`ray-2d-api.html` 和 `novelml-tags.html`。已由主任务初始浏览器冒烟确认原生引擎载入和首段显示；后续分页、条件组合、四槽、刷新恢复、旋转与负载需以最后构建重新验收。system沿用样板所需的引擎默认GUI素材，仅消息框与选择按钮按纵屏生成矩形布局；这不是正式UI设计。

## 本批次输入兼容问题

实际浏览器定位：SDK Wasm 的字母键匹配需要大写 `KeyboardEvent.key`；网页按钮与实体小写按键需在网页壳转换为大写后转发。鼠标点击可正常推进。此差异来自当前运行包，不能用文档的通用按键列表推断小写键已通过。

当前SDK文档的 `showChoosebox` 为大小写错误，Wasm实际暴露 `showChooseBox({index, showIdle, showHover})`。本样板已按二进制与官方API注册名修正，并逐项核对所用Suika API名称均存在于当前Wasm。正文并行更新后重新核对摘录，字未变，已另存 `excerpt-source.txt` 和摘录指纹，整文件指纹只对应读取时点。

同一轮API参数复核发现 `moveToLabelTag` 的实际参数是 `label`，本地文档误记为 `name`；样板跳转已统一修正。

## NovelML 参数兼容边界

当前Wasm实跑未展开文档示例中的 `${变量}`：条件一直落入else，立绘参数被当成字面路径。因此本样板使用 Ray 计算条件并跳至两套原生choose静态标签；选择提交后按白名单跳至六套静态资源/说明标签。正文、选项和图片仍由Suika原生标签显示；没有JS播放器。后续编译器需以实测语法为准，不能直接采用文档插值示例。

## 当前Wasm WebP保色兼容修复

资源对照发现当前Wasm的WebP红蓝通道颠倒，PNG UI不受影响。原WebP文件与指纹不改：每次原生bg/ch载入后，显式webp_fix取得原像素Packed视图，交换低8位和16—23位，保留G/alpha，再updateImagePixels。实际API参数统一为image。只修样板WebP背景和center层，不修PNG消息框或按钮。

读档API会重载图层原图，因此成功读档后修bg及实际存在的center各一次。center是否存在保存在原生状态，空层不调用getLayerImage；不使用有消费效果的checkRightAfterLoad，保留原生恢复行为。图片修复只发生在加载后，不按帧循环，不再次交换已修纹理。保存仅允许稳定text/choose等待态，避免在解码与修复之间存档。日志colorfix记录尺寸及Engine.millisec差值；该时钟可能逐帧更新，精确耗时由浏览器计时。
