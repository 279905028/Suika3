## 接口与实现约束

- SDK `suika3.h` 定义 `S3_NORMAL_SAVE_SLOTS=100`、`S3_ALL_SAVE_SLOTS=101`；用户四槽为0自动、1/2/3手动。
- `executeSaveLocal/executeLoadLocal/checkSaveExists/deleteLocalSave` 为槽操作；`getLatestSaveIndex()`也会包含隐藏快照，不能直接实现用户“继续阅读”。
- GUI原生 `type:save/load` 直接存取，没有本次查到的加载前验证回调。SUI-E构建派生 `type:char`，由宿主读取动作并校验后存取；缩略图等信息需宿主补绘。
- `checkRightAfterLoad()`只能作为同帧补充检测；新宿主应在自己调用成功后立即验证，再交还脚本更新。不能等下一帧才检查。
- 故事与路径字段用局部变量；设置、图鉴与快照代次用全局变量。所有必需故事字段应新游戏时显式初始化；trail按`e_depth`截断，忽略载入后残留的更深键。
- 存档只在正文/选择稳定等待态产生；脚本版本、文件/位置、稳定来源ID、内容状态、待选ID须一致。内容验证函数不自动证明原生位置与来源对应。

## 回退方案审阅

允许10～99的90槽环，每次选择存储完整原生快照，并在局部trail记录槽位、选择ID和递增代次；全局槽元数据记录当前构建与代次。恢复旧档时，先比较全局代次，读取后再比较快照内部代次。任何缺失/过期/不兼容均拒绝，不把槽复用当作同一个选择。

须在交接中明确：只保留最近90个选择快照；普通手动档仍可读，但指向已被环覆盖快照的回退可能不可用。新游戏不能清空四个用户存档或强行迁移旧版本档。完整快照恢复使本次分支的下游答案失效；不允许仅清改一个答案再跳转。

本次独立代码审阅发现自动保存节流会漏掉快速翻页后的停留页，已反馈主任务改为dirty后延期保存。正式候选修复情况以该批最终源码与浏览器报告为准。

## 补充实测与兼容修复

- SDK实际绑定为 `Suika.getTagFile()`，不是文档目录所列 `getTagFileName()`；`getTagLine()`返回1基源行号。二者已在Wasm运行，适用于只读位置表校验。
- `Suika.addHistory()`实际参数为 `message`，不是文档中的`msg`。独立探针保存前加入1条、保存后加入1条，读档后原生回顾计数为0：不残留下游内容，但也不恢复存档前的回顾。当前回顾应说明从恢复点重新累计。
- 独立探针真实刷新后，内部槽11文件仍在，但`checkSaveExists({index:11})`返回false；直接`executeLoadLocal({index:11})`成功且宿主状态/原生位置校验通过。这是SDK启动后的隐藏槽缓存边界。生产宿主对10～99应依赖项目/代次元数据做前置门禁，再直接读取原生槽；0～3继续使用存在检查。不能把缓存false误判为快照已删除。
