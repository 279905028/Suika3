先同步源码并保存外部资源，再确定一个新候选，处理或明确保留问题，重测计划支持的平台，然后生成包、标签和Release。当前更适合作为 `v1.1.0-beta.1` 等预览版准备；名称仅为建议，未创建标签或Release。

GitHub Release允许附加可下载构建，自动生成的Source code仅包含标签对应仓库内容；当前项目的大素材和运行包不会因此自动补齐。每个Release附件需小于2 GiB，现有平台包量级可容纳，完整资源归档如超过上限应拆分或另存。参考：[About releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)、[Managing releases](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。
